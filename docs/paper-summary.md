1. 面向教学与展陈场景的轻量化数字人交互系统设计与应用

## 三、创新点

围绕"低成本、可本地部署、形象可替换"三项工程目标提炼，避免空泛的"提出框架/方法"类表述：

1. **双形态数字人统一接入**：在前端层将二维卡通形象（Live2D）与真人分身形象（LiveTalking）抽象为同一类可热切换组件，通过五动作接口与两条声明性属性（是否需要外部音频、句级 / 段级投递粒度）屏蔽底层差异，使上层对话与合成模块无须感知形象方案。
2. **受限领域 RAG 工作流**：将"意图判断"与"答案生成"合并为同一次模型调用，仅产生一次推理开销；配合本地化 Dify、Qwen2.5-3B、BGE 中文向量化与 150 字回答约束，构建可脱离公网运行的知识问答模块。
3. **混合粒度的流式调度**：在前端服务接入与编排层引入"句级 / 段级"投递粒度抽象，并配合句切分缓冲、世代号取消机制，使同一对话流水线既能服务于客户端口型驱动的卡通形象，也能服务于服务端整段渲染的真人分身。
4. **中端单卡资源协同**：在 i7 + 12 GB 显存中端配置下，通过模型选型与流水线错峰调度，使语音识别、对话生成、语音合成与形象渲染同卡共存，避免按"每模块各一卡"的常规堆叠。
5. **完整本地化方案**：所有服务与模型权重均在同一台设备或同一内网内运行，规避公网带宽、第三方接口与按调用计费的依赖，契合校园机房、博物馆展厅等典型部署场景。

## 五、写法规约

### 1. 风格定位
- 行业白皮书式而非学术论文式，更接近《现代电影技术》既有刊文风格。
- "功能 + 选择 + 理由"为基本叙述单位，少用"我们提出 / 设计 / 实现"等学术句式。
- 避免代码、类名、函数名、配置项；技术机制以平实语言转译。

### 2. 章节命名
- 平铺直叙的功能性命名，例如"流式调度与句切分机制"。
- 避免"基于 X 的 Y 设计与实现"型命名。
- 不在小节中再设三级编号子标题，所有论点连续成文。

### 3. 术语统一
- **层**专指纵向抽象，本系统四层为：前端展示层 / 服务接入与编排层 / 后端服务层 / 模型层。
- **环节 / 模块 / 阶段** 用于横向流水线上的处理步骤（ASR、对话、合成、形象驱动），不与"层"混用。
- **流水线** 描述横向时序结构。
- 软化技术术语：用"缓冲"代替"句子缓冲区"、"投递粒度声明"代替"streamMode"、"世代号"代替"generation token"。

### 4. 图表使用
- 文字描述无法替代的视觉信息才用图：分层结构、时序重叠、工作流路径。
- 图与文呼应，图旁文字必须明确指引"如图 X 所示"。
- 表格用于多维并列对比，不堆罗列性条目。

### 5. 篇幅控制
- 主体章节单节优先控制在目标字数 ±10% 内。
- 超长章节先成稿再压缩，重在保留"功能 + 选择 + 理由"三段，去除铺陈与修饰。

### 6. 数据呈现
- 所有性能数字、资源占用、对比项必须有实测来源，避免估算与"显著优于"等模糊表述。
- 实验在第 4 章统一交代环境、方法与口径。
